# 配置主表与规则文件

项目只保留一个面向用户的启动入口：双击根目录的 `启动配置页.bat`，在 WebUI 的「配置」页面完成设置。配置源是 `config/配置主表.json`；运行时 JSON 由「应用配置」生成，不直接编辑。

## 首次创建和应用

1. 打开 WebUI「配置 → 常用设置」，从示例创建配置主表。
2. 填写飞书 App ID、App Secret；选择模型服务商，填写该服务商的 Key 和 API 地址，获取模型列表并选择分析模型。
3. QQ 白名单填数字群号，每行一个；飞书推送会话填 `oc_` 开头的群会话 ID，每行一个。
4. 点击「保存并应用配置」。需要改动未展示的高级字段时，可用文本编辑器修改 `config/配置主表.json`，然后在「配置 → 规则文件」点击「应用配置」。

应用操作读取主表和其中引用的 Markdown，生成或覆盖运行时文件。若正在编辑规则文件，先点击「保存文件」，再点击「应用配置」。部分选项在进程启动时读取，应用后需在网页重启对应服务。

## 主表分区

| 分区 | 内容 |
| --- | --- |
| `ports` | 机器人归档接收端和 NapCat HTTP 端口，默认分别为 5000、3000 |
| `bot` | 飞书/OneBot 运行方式、归档目录等基础参数 |
| `models` | 当前分析模型；`provider_profiles`分别保存各服务商的 Key、地址和已选模型 |
| `feishu_bot` | 当前长连接使用的 App ID 与 App Secret |
| `analysis.qq_game_sentiment` | QQ 白名单、报告时间、推送目标、分批大小、保留天数及规则引用 |
| `napcat_integration`、`napcat_bridge` | QQ/NapCat 安装路径、OneBot 消息通道与连接参数 |
| `persona` | 对话和分析规则的兼容字段；内容来自 Markdown 源文件 |

QQ 使用 NapCat 登录个人账号，无需 QQ 开放平台机器人 App ID/Secret。飞书当前采用长连接，常用设置只需要飞书 App ID、App Secret；旧配置中的机器人编号、Bot Token、Verification Token、Encrypt Key 不参与这条链路。

## Markdown 源文件

| 主表字段 | 源文件 | 应用后的用途 |
| --- | --- | --- |
| `persona.runtime.long_text_file` | `config/飞书对话规则.md` | 飞书对话和已有报告问答规则 |
| `persona.qq_analysis.long_text_file` | `config/QQ群聊分析规则.md` | QQ 群聊分析规则 |
| `task_system_prompt_file` | `config/prompts/群聊反馈报告规则.md` | 单批报告生成规则 |
| `merge_batch_system_prompt_file` | `config/prompts/分批报告合并规则.md` | 多批结果合并规则 |

「规则文件」只列出当前主表引用的原始 Markdown，不列出生成的 JSON、示例文件或说明文档。主表中以 `@file:` 开头的字段也会在应用时从指定文件读取长文本。运行时沿用 `personality_long_text` 等兼容字段名；这只是旧数据结构名称，规则内容为通用描述。

生成的文件包括 `bot_config.json`、`models.json`、`feishu_bot.json`、`analysis_config.json`、`napcat_integration.json`、`napcat_bridge.json` 和规则对应的运行时 JSON。文件内有 `_generated_from` 标记；下次应用会覆盖其中的手工改动。

## QQ 报告配置

- `group_whitelist`只填 QQ 数字群号。只有白名单群的有效文本会进入群聊归档与日报；请把示例群号替换为自己的群号。
- `feishu_push_chat_ids`填接收定时报告的飞书 `oc_` 群会话 ID。推送测试使用独立输入框，且目标需先保存到此列表；点击「发送测试消息」才会发送。
- `evening_run_at`默认 `23:00`，从当天 00:00 分析到实际执行时刻。飞书群内的 `/舆情明细`可手动分析当天至当前时刻，并回到发起命令的群。
- `max_messages_per_group: 0`表示不限制当日归档消息总数；`transcript_max_bytes_per_batch: 32768`表示单批输入最多 32 KiB，超长记录会明确报错，不会静默截断。
- `report_retention_days`默认 7 天；定时器按此设置清理旧 QQ 报告及 QQ 群日期归档。设为 0 可关闭自动清理。

## 模型接口

常用设置按服务商分开保存凭据。切换服务商会回填自己的 Key、地址和已选模型；`models.json`只写入当前生效的模型。列表请求调用兼容 OpenAI 的 `/models` 接口，测速调用聊天接口，可能产生少量模型用量。若服务商不提供模型列表，可用文本编辑器在主表中设置模型 ID，再回到网页应用配置。原生且不兼容这些接口的厂商协议不在当前实现范围内。
