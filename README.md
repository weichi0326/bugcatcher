# BugCatcher

把 QQ 群反馈归档、整理成分析报告，并推送到飞书的 Windows 本地工具。

适合在 QQ 群收集用户反馈、在飞书协作处理问题的团队。项目通过 NapCat 接收指定群聊消息，保存原始记录，再按计划或手动调用模型生成 Markdown 报告。安装、配置、扫码登录、启停和查看结果都可以在本地 WebUI 完成。

## 主要功能

- **群聊归档**：只归档白名单中的 QQ 群消息，保留可检索的记录。
- **分析报告**：按计划或飞书命令分析归档，生成带问题、证据和建议的 Markdown 报告。
- **飞书协作**：把报告推送到指定会话，并通过长连接接收命令和报告问答。
- **本地管理**：在浏览器中安装 QQ/NapCat、扫码登录、选择模型、查看状态与日志，以及浏览和删除归档、报告。

## 快速开始

### 准备条件

- Windows 和 Python 3.10 或更高版本；Python 需能从命令行调用。
- 一个 QQ 账号，以及用于归档的 QQ 数字群号。
- 飞书自建应用的 App ID、App Secret。需在飞书开放平台启用长连接、发布应用，并把机器人加入目标会话。
- 一个兼容 OpenAI 风格聊天接口的模型服务及其 API Key。

### 启动步骤

1. 下载或克隆项目，双击根目录的 **启动配置页.bat**。浏览器将打开本地管理页：`http://127.0.0.1:8088`。首次运行若缺少 Flask，启动器会尝试安装。
2. 在「运行管理」部署 Python 依赖，然后运行环境诊断。
3. 在「配置」完成三项设置，然后点击「保存并应用配置」：
   - 填写飞书 App ID 和 App Secret。
   - 选择模型服务商、填写该服务商的 Key，获取模型列表并选定分析模型。
   - 填写 QQ 群白名单和接收报告的飞书会话 ID。
4. 在「QQ 管理」点击「下载并安装 QQ」。程序会获取 NapCat 官方 OneKey 安装组件；若安装窗口要求确认，按提示完成。
5. 回到「概览」点击「启动全部」，用手机 QQ 扫描页面上的二维码。登录后可在「QQ 管理」查看账号和版本。
6. 在飞书群发送 `/help` 验证机器人。群聊消息进入归档后，可用 `/舆情明细` 生成当日报告；归档和报告也能在「记录与报告」查看。

只需运行飞书机器人时，可在「运行管理」选择「仅启动机器人」，暂时不启动 QQ。WebUI 是操作入口；机器人和 NapCat 由它管理，仍作为独立进程运行。

## 从消息到报告

```text
白名单 QQ 群 → NapCat → OneBot 接收端 → 本地聊天归档
                                      ↓
                               模型分析 → Markdown 报告 → 飞书会话

飞书消息 → 长连接 → 命令处理 / 报告问答
```

QQ 消息先保存在本机。生成报告时，相关聊天文本会发送给你配置的模型服务；启用推送时，报告会发送到指定飞书会话。项目不会把 QQ/NapCat 安装包、聊天归档或本机凭据放进仓库。

默认每天 23:00 分析当天的群聊记录，也可以在飞书用 `/舆情明细` 手动触发。报告以 Markdown 文件保存，WebUI 支持排版阅读和原文阅读。归档与报告默认保留近 7 天，可在配置中调整。

## 配置与文件

| 路径 | 用途 |
| --- | --- |
| `config/配置主表.json` | 配置源文件；首次可从 `config/配置主表.example.json` 创建 |
| `config/*.md`、`config/prompts/*.md` | 飞书对话、群聊分析和报告生成规则 |
| `conversation_logs/` | 本地 QQ 聊天归档 |
| `analysis_reports/` | 生成的 Markdown 分析报告 |

在「配置 → 规则文件」编辑当前主表引用的 Markdown 后，先保存文件，再点击「应用配置」。应用操作会生成机器人、模型和分析任务使用的运行时 JSON；后续修改应回到配置主表或 WebUI。部分设置需要重启对应服务才能生效。详细字段见 [配置说明](config/配置说明.md)。

模型 Key、API 地址和模型按服务商分别保存。模型列表与测试依赖服务商提供兼容接口；对于不提供模型列表的服务商，可在配置主表中填写模型 ID。当前实现支持 OpenAI 风格接口，不覆盖各厂商独有的原生协议。

## 实现与运行结构

| 组件 | 职责 |
| --- | --- |
| `config_ui/`、`config_web.py` | 本地 WebUI、配置和文件 API，默认使用 8088 端口 |
| `web_operations.py`、`scripts/integrated_launcher.py` | 环境诊断、服务状态及机器人与 NapCat 的启动编排 |
| `bot.py`、`botskill/` | 飞书长连接、命令处理和 OneBot 消息接收，默认使用 5000 端口 |
| `botskill/analysis/` | 归档读取、定时分析、报告生成与飞书推送 |
| `napcat_setup.py`、`napcat/` | 下载和安装 QQ/NapCat；NapCat HTTP 默认使用 3000 端口 |

WebUI 负责管理，QQ 消息由 NapCat 上报给机器人的 OneBot 接收端。端口可通过配置主表调整。关于安装目录和版本识别，见 [QQ/NapCat 使用说明](napcat/使用说明.md)。

## 常见问题

| 现象 | 先检查什么 |
| --- | --- |
| QQ 已登录，但没有新归档 | 确认群号在白名单且消息含文本；必要时到「运行管理」重写连接配置并重启全部服务 |
| 飞书没有响应 | 确认应用已发布、长连接已启用、机器人已加入会话，且凭据已保存并应用 |
| 模型列表或测试失败 | 检查当前服务商的 Key、API 地址和模型权限；部分服务商不提供模型列表接口 |
| 修改规则后未生效 | 保存 Markdown，点击「应用配置」，再按页面提示重启服务 |
