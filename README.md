# 飞书机器人与 QQ 群聊归档

这是一个在 Windows 本机运行的项目管理工具。飞书机器人通过长连接接收命令和问题；NapCat 登录 QQ，将指定群聊归档，再由模型生成 Markdown 分析报告并推送到飞书。日常配置、安装、启停、扫码、诊断及查看记录都在同一个 WebUI 中完成。

**唯一的用户启动入口是项目根目录的 `启动配置页.bat`。** 它启动本机管理页，默认地址为 `http://127.0.0.1:8088`。机器人和 NapCat 仍是独立进程，由管理页启动和管理；网页服务关闭不等于两个程序被合并为一个进程。

## 功能与页面

| 页面 | 主要用途 |
| --- | --- |
| 概览 | 启动或停止整合服务；查看飞书、QQ 登录和归档接收端状态；直接显示 QQ 登录二维码 |
| QQ 管理 | 按需下载并安装 QQ/NapCat；查看安装版本、当前账号、头像；重新扫码登录 |
| 配置 | 设置飞书凭据、模型服务商及 Key、QQ 群白名单、飞书推送会话；编辑 Markdown 规则并应用 |
| 记录与报告 | 浏览、搜索和删除聊天归档与分析报告；报告支持排版阅读和 Markdown 原文阅读 |
| 运行管理 | 部署 Python 依赖、诊断环境、查看日志；提供仅启动机器人、重启全部及修复 QQ 消息连接 |

飞书侧支持 `/help`、`/sid`、`/gsid`、`/舆情明细`、`/restart`。`/舆情明细`分析当日 00:00 至发起时刻的 QQ 群记录；默认每日 23:00 也会自动生成当日报告。`/restart`只重启机器人进程，不要求 QQ 重新扫码。普通群聊消息不会触发 QQ 侧自动回复。

## 架构

~~~text
启动配置页.bat
  └─ config_web.py（本机 WebUI 与 API，默认 127.0.0.1:8088）
       ├─ 配置读写、模型列表/测速、文件浏览与报告阅读
       └─ web_operations.py（部署、诊断、日志与子进程管理）
            └─ scripts/integrated_launcher.py（整合启动编排）
                 ├─ bot.py / botskill/bootstrap.py
                 │    ├─ 飞书 WebSocket 长连接 → 命令、报告问答、推送
                 │    ├─ OneBot HTTP 接收端 :5000/onebot → conversation_logs/
                 │    └─ 定时器 → 模型分析 → analysis_reports/
                 └─ NapCat / QQ（NapCat HTTP 默认 :3000）
                      └─ QQ 消息事件 → OneBot 接收端
~~~

管理页只是控制面：`config_web.py`监听本机 8088；QQ 消息接收端属于机器人进程，默认监听 5000；NapCat 的 HTTP 接口默认使用 3000。这些端口可由配置主表修改，不能把“统一在网页操作”理解为“只剩一个服务端口”。

### 数据如何流转

1. 飞书应用通过长连接把消息交给 `botskill/feishu_longconn.py` 和消息处理层；`commands.py`处理命令，报告问答读取已有报告。
2. QQ 由 NapCat 登录。整合启动器在登录后写入并热加载 OneBot 网络配置；群消息上报到 `/onebot`，经 `botskill/onebot_client.py`写入 `conversation_logs/`。
3. QQ 群白名单决定哪些群聊进入归档与分析；有实质文本的消息才进入文本归档。代码也支持 QQ 私聊归档，但日报取白名单群聊。飞书消息不写入 QQ 归档。
4. 手动命令或定时器读取归档，按输入大小分批调用兼容 OpenAI 聊天接口的模型，生成 Markdown 报告到 `analysis_reports/`，再推送到配置的飞书会话。定时推送失败时只重试未成功的目标。

核心模块位置：

| 路径 | 职责 |
| --- | --- |
| `config_ui/`、`config_web.py` | 浏览器页面和本机 API |
| `web_operations.py` | 环境任务、状态与进程生命周期 |
| `scripts/integrated_launcher.py` | 飞书机器人与 NapCat 的启动、登录和连接编排 |
| `bot.py`、`botskill/` | 飞书长连接、OneBot 接收、消息处理 |
| `botskill/analysis/` | 归档读取、调度、模型分析、报告与飞书推送 |
| `config/config_master.py` | 配置主表和 Markdown 规则生成运行时 JSON |
| `napcat_setup.py` | 下载、校验、启动官方 OneKey 安装组件 |

## 首次使用

需要 Windows、Python 3.10+（加入 PATH）、飞书自建应用的 App ID/App Secret、一个兼容 OpenAI 聊天接口的模型服务，以及用于扫码的 QQ。QQ/NapCat 程序包不随仓库分发，由 WebUI 按需获取官方 OneKey。

1. 双击 `启动配置页.bat`。启动器会检查 Flask，待浏览器打开管理页。可用环境变量 `QINGLAN_CFG_WEB_PORT`调整管理页端口。
2. 在「运行管理」点击「开始部署」安装项目依赖，再点击「开始检测」。诊断会区分程序执行失败与检测到环境问题；缺少 QQ/NapCat 时，先到下一步安装。
3. 在「配置 → 常用设置」从示例创建主表，填写飞书 App ID/App Secret；选择模型服务商，填入该服务商的 Key，获取模型列表后选定分析模型；填写 QQ 数字群号和接收日报的飞书 `oc_` 会话 ID，点击「保存并应用配置」。
4. 在「QQ 管理」点击「下载并安装 QQ」。如果安装程序弹出确认窗口，按提示完成；页面会识别 QQ 和 NapCat 版本。
5. 在「概览」点击「启动全部」，用手机 QQ 扫描网页二维码。登录后页面显示账号信息，整合启动器会配置 QQ 消息连接。飞书应用还需在开放平台启用**长连接**、发布应用并加入目标飞书群。
6. 在飞书群发送 `/help`检查命令；有 QQ 群消息进入归档后，可用 `/舆情明细`试生成当日报告。

只需要飞书而暂不登录 QQ 时，使用「运行管理 → 仅启动机器人」。切换回整合模式可在概览或运行管理中启动全部。网页上的「推送测试」使用独立的会话 ID 和消息文本框，点击发送按钮后才会发出测试消息。

## 配置与规则

配置源文件是 `config/配置主表.json`，首次可从 `config/配置主表.example.json`创建。WebUI 的「常用设置」只展示最常用字段；其他字段可用文本编辑器修改主表，再回到「配置 → 规则文件」点击「应用配置」。应用操作由 `config/config_master.py`生成 `bot_config.json`、`models.json`、`analysis_config.json`、NapCat 配置等运行时 JSON。**这些生成文件不是配置源，不应直接编辑。**

「规则文件」只显示当前主表引用的 Markdown 源文件，例如飞书对话、QQ群聊分析和报告生成规则。修改后先保存文件，再点击「应用配置」写入对应运行时 JSON。部分启动时读取的设置需要在网页重新启动机器人或整合服务后生效。

模型设置按服务商分别保存 Key、API 地址和模型；切换服务商会回填各自资料。模型列表和测速会请求该服务商接口；自定义地址需兼容 OpenAI 风格的模型列表与聊天接口。不提供模型列表的厂商，可以直接编辑配置主表中的模型 ID。当前实现不承诺兼容各厂商独有的原生 API 协议。

更多字段与规则文件说明见 [配置说明](config/配置说明.md)。

## 日常使用与排查

| 情况 | 操作 |
| --- | --- |
| 查看服务是否真的启动 | 在「概览」看飞书、QQ 登录、归档接收端的独立状态；在「运行管理」看服务输出 |
| 更换 QQ 账号 | 在「QQ 管理」点击「重新扫码登录」；整合服务会重启并显示新二维码 |
| QQ 已登录但没有归档消息 | 确认群号在白名单、消息含文本；再到「运行管理」执行「重写连接配置」并重新启动全部 |
| 飞书不响应 | 确认已发布应用、启用长连接、机器人已加入群，且凭据已应用；查看运行日志 |
| 模型列表或测试失败 | 检查当前服务商的 Key、API 地址、模型权限及错误提示 |
| 修改规则后无变化 | 保存 Markdown，点击「应用配置」，再按页面提示重启对应服务 |

定时报告默认在 23:00 运行，分析当日 00:00 至实际触发时刻；错过计划时刻会在服务恢复后补跑。默认保留近 7 天 QQ 报告和 QQ 群归档日期目录，可在配置主表调整；管理页也提供单份归档和报告的删除操作。关于 QQ/NapCat 的安装目录和版本识别，见 [NapCat 使用说明](napcat/使用说明.md)。

## 发布到 GitHub 与开发验证

项目的 `.gitignore`排除本机配置主表、生成的运行时 JSON、归档、报告、日志及 QQ/NapCat 安装包；提交源码、示例配置和通用 Markdown 规则即可。上传前可运行 `python scripts/check_github_safe.py`检查拟提交内容，并核对 `git status`。QQ/NapCat 安装包通常较大，保持按需下载。

开发验证命令：

~~~powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -q
node --check config_ui/app.js
~~~

测试与维护脚本是开发工具。日常用户只需要从 `启动配置页.bat`进入 WebUI。
